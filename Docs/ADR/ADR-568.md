# ADR-568 asmdef 공통 설정과 추가 금지 방향

- Status: Validated
- SourceStep: 17 / M0 (2026-11-25, 사용자 승인)
- Related: ADR-479, ADR-480, ADR-481, ADR-563 / Handover 16-17 / UNITY_T002

## Context
Handover 16-17은 계층별 asmdef와 허용 방향(Application→Domain, infra/adapters→contracts, Presentation→Application/Domain/adapters, Bootstrap→전부)을 정하지만, asmdef 세부 설정과 계층 사이 금지 방향은 적지 않았다.

## Decision
- 8개 asmdef: Domain, Application, Infrastructure, UnityAdapters, Presentation, Bootstrap, Editor(Editor 전용), Tests.EditMode(Editor 전용, `UNITY_INCLUDE_TESTS`, `nunit.framework.dll`).
- 모든 런타임 asmdef `autoReferenced: false`, 이름 참조, `rootNamespace`는 어셈블리 이름과 동일.
- 추가 금지 방향: Infrastructure↔UnityAdapters 상호 참조, UnityAdapters→Presentation.
- Unity 패키지 참조는 실제 사용 시점에 추가.
- 스크립트가 없는 asmdef는 어셈블리가 만들어지지 않으므로 각 어셈블리에 `AssemblyInfo.cs`(`InternalsVisibleTo("PastFuture.Tests.EditMode")`만 포함)를 둔다.
- 규칙은 `AssemblyBoundaryTests`가 `.asmdef` 파일을 직접 읽어 검사한다.

## Consequences
- 계층 추가·변경 시 asmdef와 `AssemblyBoundaryTests.AllowedProjectReferences`를 함께 바꿔야 한다.

## ValidationEvidence
- 2026-11-25 batchmode EditMode 5/5 Passed (커밋 af4dd26): `UNITY_T002_ProjectAsmdefs_FollowLayerRules`, `UNITY_T002_ProjectAsmdefs_HaveNoCycles` 포함.
- Presentation→Infrastructure 참조를 일부러 추가한 실행에서 `FollowLayerRules`가 Failed.
- 순환 참조의 실패 사례는 실행하지 못했다. Unity가 순환 asmdef를 컴파일 단계에서 거부하기 때문이다.
