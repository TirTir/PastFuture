# ADR-566 Git LFS 대상에 일반 이미지(.png/.jpg) 포함

- Status: Accepted
- SourceStep: 17 / M0 (2026-11-25, `.gitattributes` 초안 승인)
- Related: Handover 14.2, 16-18

## Context
Handover 14.2는 "대형 바이너리 LFS 선택 적용"이라고만 적고 원본 텍스처(`.psd`, `.exr`) 등을 예로 든다. 일반 이미지 포맷의 포함 여부는 정하지 않았다.

## Decision
`.gitattributes`에서 `.png`, `.jpg`, `.jpeg`, `.tga`, `.tif(f)`, `.hdr`, `.psd`, `.psb`, `.exr`를 모두 LFS로 추적한다. 모델, 오디오, 영상, 폰트, 압축 파일, 네이티브 라이브러리, `LightingData.asset`도 LFS다. Unity YAML(`.unity`, `.prefab`, `.asset`, `.meta` 등)과 코드·문서는 일반 Git이다.

## Alternatives
- `.png`/`.jpg`는 일반 Git: 작은 UI 이미지에 LFS 용량을 쓰지 않지만, 원본 이미지가 커지면 히스토리가 불어남.

## Consequences
- 작은 이미지도 GitHub LFS 저장 용량과 대역폭을 사용한다.
- clone 환경에 Git LFS가 필요하다.

## ValidationEvidence
- 2026-11-25 첫 커밋(1237ee3)에서 `URP.png`가 LFS 포인터로 저장되고, 새 clone에서 실제 파일로 복원(sha256 일치)됨을 확인.
- UnityYAMLMerge(smart merge) 연결은 결정하지 않았다.
