# ADR-563 Application 어셈블리도 엔진 참조 금지

- Status: Validated
- SourceStep: 17 / M0 (2026-11-25, 사용자 승인)
- Related: ADR-479, ADR-480, ADR-568 / Handover 16-1, 16-17, 16-18 / UNITY_T001

## Context
Handover 16-17은 Domain에 대해서만 "No Engine References"를 명시한다. 16-18의 `HeadlessSimulationRunner` 후보는 순수 .NET에서 SimulationCoordinator와 Command Dispatcher를 실행해야 하며, 이들은 16-1에서 Application 책임이다.

## Decision
`PastFuture.Application` asmdef도 `noEngineReferences: true`, `overrideReferences: true`(precompiled 참조 없음)로 둔다. Application이 필요로 하는 Unity 기능(시간, 파일 경로, 플랫폼 등)은 Application에 인터페이스를 두고 Infrastructure 또는 UnityAdapters에서 구현한다.

## Alternatives
- Domain만 엔진 금지 (Handover 문구 그대로): headless 실행 시 Application을 쓸 수 없게 될 위험.

## Consequences
- Application 코드에서 `UnityEngine` 타입을 쓰면 컴파일 단계에서 막힌다.
- 포트(인터페이스) 수가 늘어난다.

## ValidationEvidence
- 2026-11-25 Unity 6000.3.29f1 batchmode EditMode: `UNITY_T001_EngineFreeAssembly_DoesNotReferenceUnity("PastFuture.Application")`, `UNITY_T001_EngineFreeAsmdef_HasNoEngineReferencesFlag` Passed (커밋 af4dd26).
- 같은 날 Application의 `noEngineReferences`를 일부러 `false`로 바꾼 실행에서 `HasNoEngineReferencesFlag`가 Failed (되돌린 뒤 다시 Passed).
- 순수 .NET(`dotnet test`) headless 실행은 아직 하지 않았다.
