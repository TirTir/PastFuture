# ADR-569 Bootstrap 최소 씬, LifetimeScope 계약, Manual DI 규칙 (M0)

- Status: Accepted
- SourceStep: 17 / M0 (2026-11-25, 사용자 승인 "권장안대로 진행", "스크립트로 자동화")
- Related: ADR-009, ADR-010, ADR-395, ADR-481, ADR-482, ADR-484, ADR-565, ADR-567 / Handover 16-1, 16-17, 4.1-3 / UNITY_T003, UNITY_T008

## Context
- Handover 4.1-3은 M0에 "최소 씬 및 asmdef, Manual DI"를 요구한다.
- 16-17은 다음을 정한다.
  - Manual constructor DI를 쓴다.
  - 시작 순서는 Bootstrap Scene → App registry/save/profile → menu → Session → Loop → Scene → bindings → simulation이다.
  - MonoBehaviour는 view/adapter 역할만 하고 WorldState를 직접 쓰지 않는다.
- 16-1은 Application/Profile/Session/Loop/Scene/Prediction Scope를 분리하고, Scope가 끝날 때 구독과 비동기 작업을 해제·취소하라고 한다.
- Handover에 없는 것:
  - Scope 해제의 세부 계약
  - Bootstrap 씬 구성
  - DI 금지 사항
- ADR-009/010/481/482는 제목이나 요약만 남아 있다.

## Decision
1. **Bootstrap 씬**
   - 경로는 `Assets/PastFuture/Scenes/Bootstrap.unity`이고, 안에 `Bootstrap` GameObject 하나와 `GameBootstrapper` 컴포넌트만 둔다.
   - Build 씬 목록은 Bootstrap 하나(0번)만 둔다. 템플릿 `Assets/Scenes/SampleScene.unity`는 목록에서만 빼고 파일은 남긴다 (ADR-567 보류 항목 유지).
   - 씬 파일은 사용자가 Editor에서 만든다.
   - Build 목록은 `PastFuture.Editor.Build.BuildSceneList.Apply`로 설정한다. batchmode `-executeMethod`로 실행하거나, 메뉴 PastFuture/Build/Apply Build Scene List로 실행한다. `EditorBuildSettings.asset`을 손으로 고치지 않는다.
2. **GameBootstrapper** (`PastFuture.Bootstrap`, MonoBehaviour)
   - `[DefaultExecutionOrder(-10000)]`, `[DisallowMultipleComponent]`
   - Awake에서 `CompositionRoot`를 한 번만 만들고 `DontDestroyOnLoad`를 건다. 두 번째 인스턴스는 경고를 남기고 스스로 파괴된다.
   - OnDestroy에서 `CompositionRoot`를 해제한다. Play 종료와 앱 종료가 모두 여기에 해당한다.
   - static 상태는 `s_active` 하나뿐이다. `[RuntimeInitializeOnLoadMethod(SubsystemRegistration)]`에서 null로 초기화한다.
3. **CompositionRoot** (`PastFuture.Bootstrap`)
   - 서비스를 생성하고 연결하는 유일한 곳이다.
   - M0에서는 Application scope만 만든다. 16-17의 나머지 단계는 해당 서비스가 생길 때 순서대로 추가한다.
4. **LifetimeScope 계약** (`PastFuture.Application.Lifecycle`, 엔진 참조 없음)
   - `ScopeKind`: Application, Profile, Session, Loop, Scene, Prediction (16-1)
   - `CreateChild(kind)`로 부모·자식 관계를 만든다. 자식의 `Cancellation`은 부모 token과 연결된다.
   - `Dispose` 순서:
     1. token을 취소한다.
     2. 자식 scope를 최신 것부터 해제한다.
     3. 등록된 `IDisposable`을 등록 역순으로 해제한다.
   - 해제 중 예외가 나도 나머지 항목을 모두 해제하고, 예외는 마지막에 `AggregateException` 하나로 모아 던진다.
   - 두 번째 `Dispose`는 아무것도 하지 않는다. 해제된 뒤의 `Register`/`CreateChild`는 `ObjectDisposedException`이다. `Register(null)`은 `ArgumentNullException`이다.
   - 자식을 먼저 해제하면 부모에서 떨어지고, 부모 token은 취소되지 않는다.
   - thread-safe가 아니다. 생성, 등록, 해제는 소유 스레드(main)에서만 한다.
5. **Manual DI 규칙**
   - 의존성은 생성자 인자로 받는다. Service Locator, DI 컨테이너, static singleton과 전역 가변 static을 쓰지 않는다. 예외는 2번의 bootstrap 감지용 static 하나다.
   - 수명이 있는 서비스는 CompositionRoot만 `new` 한다. Domain 값 객체나 서비스 내부의 임시 객체는 여기에 해당하지 않는다.
   - MonoBehaviour는 의존성을 명시적인 `Initialize(...)`로 받는다. `FindObjectOfType`, 싱글톤 `Instance` 같은 조회로 얻지 않는다.
   - 해제가 필요한 객체는 소유 scope에 `Register`한다.
6. **Test ID가 없는 테스트**
   - Handover에 대응하는 Test ID가 없는 테스트는 이름에 ID 접두사를 붙이지 않는다.
   - ProjectStatus 테스트 기록에는 "Handover ID 없음"으로 적는다.
   - 새 Test ID를 만들거나, 원문에 의미가 없는 ID에 의미를 붙이지 않는다.

## Alternatives
- **DI 컨테이너(VContainer, Zenject 등):** 채택하지 않았다. Handover 16-17과 ADR-482가 생성자 기반 Manual DI를 정했다.
- **`RuntimeInitializeOnLoadMethod(BeforeSceneLoad)`로 씬 없이 자동 bootstrap:** 채택하지 않았다. 16-17이 Bootstrap Scene에서 시작한다고 정했다.
- **`EditorBuildSettings.asset` 직접 편집:** 채택하지 않았다. Unity가 관리하는 YAML이므로 Editor API로 바꾼다.
- **테스트에 임시 ID 부여:** 채택하지 않았다. Handover의 Test ID 체계를 오염시킨다.

## Consequences
- Editor에서 Bootstrap이 아닌 씬을 열고 Play하면 `CompositionRoot`가 만들어지지 않는다. 자동 로드 여부는 미결정이다 (ProjectStatus 6절).
- Build 씬을 추가할 때는 `BuildSceneList.ScenePaths`를 고친 뒤 같은 방법으로 실행한다.
- UNITY_T003(서비스 한 번만 생성)과 UNITY_T008(PlayMode 반복 시 static 혼입 없음)은 PlayMode 자동 테스트가 필요하다. ADR-565에 따라 M1까지 NotRun이다.
