# ADR-565 PlayMode 테스트 어셈블리는 M1에서 생성

- Status: Validated (2026-11-26 M1에서 생성)
- SourceStep: 17 / M0 (2026-11-25, 사용자 승인)
- Related: Handover 16-17 폴더 구조(`Assets/Tests/{EditMode,PlayMode}`), 16-18, 4절 M0/M1

## Context
M0 완료 기준은 EditMode/순수 C# smoke이며, PlayMode가 필요한 입력·물리·카메라 검증은 M1 범위다.

## Decision
M0에서는 `PastFuture.Tests.EditMode`만 만든다. `PastFuture.Tests.PlayMode`는 M1에서 첫 PlayMode 테스트와 함께 만들고, 그때 `AssemblyBoundaryTests`의 허용 표에 등록한다.

## Consequences
- M0에는 빈 PlayMode 어셈블리가 없다.
- M1 시작 시 asmdef와 경계 테스트 갱신이 필요하다.

## Implementation (2026-11-26, M1 1단계, 사용자 승인 "1번부터 진행")
- **`Assets/Tests/PlayMode/PastFuture.Tests.PlayMode.asmdef`**
  - 참조: `UnityEngine.TestRunner`, `PastFuture.Application`, `PastFuture.Bootstrap`. 지금 쓰는 것만 넣었다.
  - `UnityEditor.TestRunner`는 넣지 않았다. 나중에 Player에서도 돌릴 수 있게 Editor 전용 참조를 피한다.
  - `includePlatforms: []`(Editor 전용 아님), `autoReferenced: false`, `defineConstraints: UNITY_INCLUDE_TESTS`, `overrideReferences: true` + `nunit.framework.dll`. 테스트를 포함하지 않는 빌드에는 들어가지 않는다.
- **`AssemblyBoundaryTests.AllowedProjectReferences`**: `PastFuture.Tests.PlayMode`의 허용 참조를 EditMode 테스트와 같은 "런타임 계층 전부"로 등록했다. Editor 전용 목록에는 넣지 않았다.
- **테스트 접근:** `GameBootstrapper`에 `internal CompositionRoot Root` 읽기 전용 속성을 추가하고, `PastFuture.Bootstrap`에 `InternalsVisibleTo("PastFuture.Tests.PlayMode")`를 추가했다. 동작은 바꾸지 않았다.
- **첫 테스트** (`Assets/Tests/PlayMode/Bootstrap/BootstrapPlayModeTests.cs`):
  - `UNITY_T003_BootstrapSceneLoadedTwice_KeepsSingleCompositionRoot`: Bootstrap 씬을 두 번 불러도 `GameBootstrapper`는 하나이고, `CompositionRoot`는 같은 인스턴스이며 해제되지 않는다. 중복 경고 로그도 확인한다.
  - `UNITY_T008_BootstrapRestartedInSameDomain_CreatesFreshRootAndDisposesPrevious`: 같은 도메인에서 Bootstrap 세션을 끝내고(객체 파괴) 다시 시작하면, 이전 root는 해제되고 새 root가 만들어지며 중복으로 취급되지 않는다.
  - UNITY_T008의 범위: Domain Reload를 끈 상태의 Play 반복과 같은 조건(정적 상태가 남는 경우)을 재현한다. Editor에서 Play/Stop 버튼을 실제로 반복하는 것은 자동화하지 않았다. 현재 프로젝트 설정은 Domain/Scene Reload를 모두 켠 상태(`m_EnterPlayModeOptions: 0`)다.
  - 각 테스트 뒤 `DontDestroyOnLoad`에 남은 `GameBootstrapper`를 파괴한다.

## ValidationEvidence
- 2026-11-26 Unity Editor가 원래 프로젝트를 열고 있었고, 창을 앞으로 가져와도 자동 새로 고침이 일어나지 않았다. 그래서 작업 트리를 scratchpad 사본에 동기화한 뒤 batchmode로 실행했다. 새 `.meta` 4개는 이 사본에서 Unity가 만든 것을 원래 프로젝트로 옮겼다.
  - PlayMode: **2/2 Passed**, exit 0, 컴파일 경고·오류 0건 (`-nographics` 없이 실행).
  - EditMode: **14/14 Passed**, exit 0 (PlayMode asmdef를 등록한 경계 테스트 포함).
  - headless `dotnet test`: 2/2 Passed.
- 음성 확인 (사본에서만 변경 후 되돌림): `GameBootstrapper`의 중복 검사와 `_root.Dispose()`를 없애자 두 테스트가 모두 Failed였다. UNITY_T003은 `Expected log did not appear: ... Duplicate GameBootstrapper destroyed`, UNITY_T008은 `Ending a session must dispose its root.` 메시지로 실패했다. 되돌린 뒤 2/2 Passed.
- 테스트 실행 뒤 사본의 `ProjectSettings/`, `Packages/`, `Assets/`(.meta 제외)에서 원래 프로젝트와 다른 파일은 없었다.
- 원래 프로젝트의 Editor에서는 아직 이 어셈블리를 컴파일하지 않았다.
