# ADR-571 Mac에서 Windows Development Build 경로 (M0)

- Status: Accepted
- SourceStep: 17 / M0 (2026-11-25, 사용자 위임 "알아서 해")
- Related: ADR-520, ADR-551, ADR-569 / Handover 4절 M0 "Windows 경로 확인", 16-17, 16-18 / UNITY_T049

## Context
- **M0 완료 기준 (Handover 4절):** "Windows 경로 확인"이 들어 있다. 출시 목표는 Windows/Steam이다 (부록 A).
- **16-17:**
  - Mono로 초기 개발을 하고, Windows 출시 때 Mono와 IL2CPP를 비교한다.
  - 우선 후보 그래픽 API는 Mac Metal, Windows D3D11이다.
- **16-18의 Windows 빌드 후보 명령:** `-batchmode -quit -projectPath ... -buildTarget StandaloneWindows64 -executeMethod PastFuture.Editor.Build.BuildWindows -logFile ...`
  - 이 Editor method는 "실제 Editor method는 미구현"으로 적혀 있다.
  - BuildReport가 실패하면 CI 실패로 처리한다.
- **원문 한계:** ADR-520(Mac 개발 및 Windows 빌드 분리 검증)과 ADR-551(Windows 자동 빌드 및 실제 실행 검증)은 제목만 남아 있다.
- **이 Mac의 모듈:** 이 Mac의 Unity 6000.3.29f1 모듈 목록에 Windows용으로는 `windows-mono`와 `windows-server`만 있고, Windows IL2CPP는 없다.

## Decision
- Unity 모듈 **Windows Build Support (Mono)**(`windows-mono`)를 설치한다. 설치 방법은 Unity CLI `unity install-modules --editor-version 6000.3.29f1 -m windows-mono`다.
- **`PastFuture.Editor.Build.BuildWindows.Run`** (`Assets/Editor/Build/BuildWindows.cs`)
  - Handover 후보 명령의 `-executeMethod`에는 클래스 이름만 있다. Unity는 `Class.Method` 형식이 필요하므로 메서드 이름 `Run`을 붙였다.
  - 대상은 `StandaloneWindows64`, 옵션은 `BuildOptions.Development`다.
  - 씬은 Build Profiles 씬 목록(ADR-569 `BuildSceneList`)의 enabled 씬을 쓴다. 목록이 비어 있으면 예외를 던진다.
  - 출력 경로는 `Builds/Windows/PastFuture.exe`이고, `.gitignore`의 `/Builds/`로 제외된다.
  - 결과, 출력 경로, scripting backend, 씬, 크기, 오류·경고 수, 걸린 시간을 로그에 남긴다.
  - `BuildResult.Succeeded`가 아니면 예외를 던진다. 그러면 batchmode가 exit 1로 끝난다.
  - Editor 메뉴 PastFuture/Build/Windows Development Build로도 실행할 수 있다.
- **scripting backend:** 현재 Standalone은 Mono(`Mono2x`)이고 바꾸지 않는다. Windows IL2CPP 빌드는 Windows 호스트가 필요하므로 비교는 Windows 장비를 확보한 뒤로 미룬다.
- **실제 Windows 실행 확인:** UNITY_T049 등은 Windows 장비가 확인되지 않아 NotRun이다.

## Alternatives
- **M0에서 보류:** 채택하지 않았다. Mac에서 확인할 수 있는 범위(모듈, 빌드 가능 여부)는 M0에서 확인한다.
- **IL2CPP 우선:** 채택하지 않았다. Mac에서는 Windows IL2CPP를 만들 수 없고, 16-17이 Mono 초기 개발을 정했다.
- **Handover 후보 명령의 클래스 이름 그대로 실행:** 그대로는 `-executeMethod`가 동작하지 않는다.

## Consequences
- **Windows 빌드 경로:** 2026-11-25 현재 Mac에서 Windows Mono Development Build를 만들 수 있다. 실제 Windows에서 실행·Profiler(UNITY_T049), D3D11/D3D12 동작, Mac↔Windows 저장·결정론(UNITY_T048, SAVE_T056, DET_T008)은 미확인이다.
- **빌드 시 바뀌는 tracked 파일:** 빌드나 처음 import할 때 Unity가 tracked 설정 파일을 다시 저장할 수 있다. 처음 import한 사본에서 빌드했을 때 아래 파일이 바뀌었다.
  - `ProjectSettings/ProjectSettings.asset`: `m_BuildTargetBatching`에 Standalone 추가
  - `ProjectSettings/UnityConnectSettings.asset`: `m_Enabled` 0→1
  - `Assets/Settings/PC_RPAsset.asset`: URP prefiltering 값
  - `DefaultVolumeProfile.asset`, `UniversalRenderPipelineGlobalSettings.asset`
  - 빌드 뒤에는 `git status`를 확인하고, 이런 변경을 검토 없이 커밋하지 않는다.
- **용량:** 출력은 약 157MB이고 Git에서 제외된다. Burst 디버그 정보 폴더(`*_BurstDebugInformation_DoNotShip`)가 같이 생기며, 배포물에서 빼야 한다.

## ValidationEvidence
- 2026-11-25 `unity install-modules ... -m windows-mono`: success. 설치 위치는 `PlaybackEngines/WindowsStandaloneSupport`(978MB)이고, `modules.json`에서 `windows-mono selected: true`다.
- 같은 날 Unity Editor가 원래 프로젝트를 열고 있어서 저장소 작업 트리를 scratchpad에 복사했다(`.git`, `Library`, `Temp` 등 제외). 이 사본에서 batchmode로 `-buildTarget StandaloneWindows64 -executeMethod PastFuture.Editor.Build.BuildWindows.Run`을 실행했다.
  - exit 0, `Build Finished, Result: Success.`
  - 로그: `Windows build Succeeded ... backend=Mono2x, scenes=[Assets/PastFuture/Scenes/Bootstrap.unity], size=164202523 bytes, errors=0, warnings=0, time=00:00:32.67`
  - `PastFuture.exe`를 `file`로 확인한 결과는 `PE32+ executable (GUI) x86-64, for MS Windows`다.
  - `PastFuture_Data/Managed`에 런타임 어셈블리 6개(`PastFuture.Domain` ~ `PastFuture.Bootstrap`)가 들어 있다.
- 같은 사본에서 batchmode EditMode **14/14 Passed**, exit 0, 컴파일 경고·오류 0건.
- `BuildWindows.cs.meta`는 이 사본에서 Unity가 만든 파일을 원래 프로젝트로 옮긴 것이다. 원래 프로젝트에는 아직 그 `.meta`가 없었다.
- 원래 프로젝트의 Unity Editor에서는 아직 컴파일·실행하지 않았다.
