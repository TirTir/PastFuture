# ADR-570 순수 .NET headless smoke 프로젝트 (Tools/Headless)

- Status: Validated
- SourceStep: 17 / M0 (2026-11-25, 사용자 승인 "권장안대로 진행")
- Related: ADR-002, ADR-530, ADR-545, ADR-550, ADR-563, ADR-569 / Handover 4절 M0, 16-17, 16-18

## Context
- **M0 완료 기준 (Handover 4절):** EditMode smoke와 순수 C# smoke가 따로 적혀 있다.
- **16-18의 요구:**
  - 순수 .NET headless와 Unity `-batchmode`는 별도로 둔다.
  - headless도 Unity와 같은 소스와 계약을 참조하고, API 호환성을 검증한다.
  - CI 순서는 Domain Unit/Integration → Unity EditMode/PlayMode다.
  - .NET 8 SDK는 예시 후보일 뿐이고, Unity와 공유하는 API 범위를 먼저 검증해야 한다.
- **지금까지의 처리:** 엔진 참조가 없는 어셈블리를 EditMode에서 검사하는 것으로 대신해 왔다. 이 검사도 Unity 안에서 돌기 때문에 위 기준의 "별도 headless"에 해당하지 않는다.
- **원문 한계:** ADR-530(순수 C# Headless Simulation)은 제목만 남아 있다. HeadlessSimulationRunner는 후보로만 적혀 있다.

## Decision
- **위치:** 저장소의 `Tools/Headless/`. Handover 16-17의 최상위 폴더 목록에 있는 `Tools/`를 쓴다. `Assets/` 밖이라 Unity가 import하지 않는다.
- **구성:**
  - `global.json`: SDK `10.0.100`, `rollForward: latestFeature`. 컴퓨터의 기본 SDK가 11이어도 이 폴더에서는 10.0.x LTS를 쓴다.
  - `Directory.Build.props`: `LangVersion 9.0`(Unity 6.3과 같은 버전), `Nullable`과 `ImplicitUsings`는 끈다. 이 파일은 `Tools/Headless` 아래 프로젝트에만 적용되고, 루트의 Unity 생성 csproj에는 영향을 주지 않는다.
  - `PastFuture.Domain.Headless.csproj`: `netstandard2.1`, 어셈블리 이름은 `PastFuture.Domain`. `Assets/PastFuture/Scripts/Domain/**/*.cs`를 고치거나 복사하지 않고 그대로 컴파일한다. Unity DLL은 참조하지 않는다.
  - `PastFuture.Application.Headless.csproj`: 위와 같은 방식이다. Domain만 참조하며, asmdef의 참조와 같다.
  - `PastFuture.Tests.Headless.csproj`: `net10.0`. 패키지는 NUnit 4.6.1, NUnit3TestAdapter 6.3.1, Microsoft.NET.Test.Sdk 18.12.0으로 고정한다.
- **smoke 범위:**
  - 엔진 없이 Domain/Application이 로드되고, 둘 다 `Unity*` 어셈블리를 참조하지 않는지 확인한다.
  - `LifetimeScope`의 해제 순서와 취소가 headless에서도 동작하는지 확인한다.
  - Handover에 대응하는 Test ID가 없으므로 이름에 ID 접두사를 붙이지 않는다 (ADR-569 6번).
- **포함하지 않는 것:** Bootstrap, `CompositionRoot`, Unity 계층(Infrastructure 이하). 이쪽은 계속 Unity EditMode가 검증한다.
- **`.gitignore`:** `/Tools/Headless/**/*.csproj`는 손으로 작성하는 파일이라 추적한다. `bin/`과 `obj/`는 제외한다. 루트의 `*.sln`/`*.slnx` 제외 규칙은 그대로 두고, sln 없이 csproj를 직접 실행한다.

## Alternatives
- **EditMode 대체를 정식 해석으로 확정:** 채택하지 않았다. "순수 .NET headless와 Unity -batchmode는 별도"라는 16-18 문장과 맞지 않는다.
- **M1로 이월:** 채택하지 않았다. M0 완료 기준에 들어 있는 항목이고, 이미 검증할 대상(`LifetimeScope`)이 있다.
- **소스를 복사하거나 공유 라이브러리 DLL을 Unity에 넣기:** 채택하지 않았다. Unity와 같은 소스를 참조한다는 원칙에 어긋나고, 소스가 두 벌이 될 위험이 있다.
- **.NET 8 SDK:** 채택하지 않았다. 2026-11에 지원이 끝나므로 LTS인 10을 택했다(사용자 선택).

## Consequences
- 새 엔진 무관 소스 폴더를 추가해도 glob에 포함되어 자동으로 headless 빌드에 들어간다. 반대로 `UnityEngine`을 쓰는 코드가 들어오면 headless 빌드가 실패한다.
- 새 엔진 무관 asmdef를 추가하면 대응하는 headless csproj도 함께 추가해야 한다.
- headless 테스트에서 Unity 쪽 타입을 쓸 수 없으므로, EditMode 테스트 파일을 그대로 공유하지 않는다.
- NuGet 복원에 네트워크가 필요하다. 패키지 버전은 고정되어 있다.

## ValidationEvidence
- 2026-11-25 `dotnet test Tools/Headless/PastFuture.Tests.Headless/PastFuture.Tests.Headless.csproj`: SDK 10.0.404, **2/2 Passed**, exit 0.
- 같은 날 `dotnet build --no-incremental`: 경고 0개, 오류 0개.
- 음성 확인: `UnityEngine.Debug.Log`를 쓰는 임시 파일을 Domain headless 빌드에 넣자 `error CS0103`('UnityEngine' 이름 없음)로 실패했다. 임시 파일은 scratchpad에 있었고 csproj 변경과 함께 되돌렸다. 되돌린 뒤 다시 2/2 Passed.
- "워크로드를 확인하는 동안 문제가 발생했습니다"라는 SDK 안내가 출력되었으나 빌드와 테스트 결과에는 영향이 없었다. 원인은 미확인이다.
